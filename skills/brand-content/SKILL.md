# Brand Content

Follow `CONTENT_RULES.md`. Pair with the `brand-visuals` skill when a post needs a graphic.

## Process

1. Ask for the real source material if it is missing: the bug, decision, concept or project the post is about. Don't invent experiences.
2. Propose 3 to 5 post ideas as one-line angles, each tied to something Bhavy has actually done or learned. Say which source each comes from.
3. For the chosen idea, draft: hook (one plain line), body (3 to 8 short lines or one small code block), close (takeaway or one honest question).
4. Offer a matching graphic using `brand-visuals`: one headline, one supporting line, optional small code block.
5. Run the checklist below and fix before delivering.

## Rules

- One idea per post. Shorter is better.
- Plain, specific, calm. Engineer to colleague.
- Never invent metrics, counts, results or experiences. If a number is needed, tell Bhavy what to measure.
- No buzzwords, no emoji, no exclamation marks, no hashtag walls, no engagement bait.
- Avoid machine-sounding patterns: "It's not X, it's Y", rhetorical-question hooks, rule-of-three padding, heavy em-dashes, summary lines that restate the post.
- Don't overstate ownership or scope.

## Checklist

1. True, and defensible in an interview?
2. Teaches or shows one specific thing?
3. Would Bhavy say this out loud to a colleague?
4. Anything that only exists to sound impressive? Cut it.
5. Graphic follows `DESIGN_RULES.md`?
